# مهاجرت از IndexedDB / Firestore به Google Sheets برای پیام جدول

## معماری
- `https://nimania.github.io/jadval/sheets-studio.html`: رابط مستقل تولید از بانک خصوصی Google Sheets
- `https://github.com/nimania/jadval`: موتور تولید و UI؛ بانک داده خصوصی در GitHub یا GitHub Pages منتشر نمی‌شود.
- شیت مرجع: [بانک مرکزی جدول فارسی](https://docs.google.com/spreadsheets/d/1u0dv4WNjQAz3QYleYDCbUkHDTWrLwxpYVDzCRl78p7E/edit)
- شیت صف ورود: [منابع و سرنخ‌های جدید](https://docs.google.com/spreadsheets/d/1Ua-YzDL-6jIHzOQsV7YKQEmBh9KmuGxjGHuWm8blLUg/edit)

## فعال‌سازی اتصال
1. در Google Cloud Console یک پروژه با Google Sheets API فعال داشته باشید (Firebase/Firestore لازم نیست).
2. در Google Auth Platform، یک OAuth client از نوع **Web application** بسازید.
3. دامنهٔ Authorized JavaScript origins را دقیقاً `https://nimania.github.io` قرار دهید. برای جریان Token Model به redirect URI نیازی نیست.
4. در صورت Testing بودن OAuth consent screen، حساب گوگلِ صاحب شیت را به test users اضافه کنید.
5. Client ID عمومی پروژهٔ `jadval-studio` در `sheets-studio.html` پیکربندی شده و خودکار در صفحه قرار می‌گیرد. مقدار ذخیره‌شدهٔ یک کلاینت قدیمی در مرورگر جای آن را نمی‌گیرد. به هیچ وجه Client Secret یا توکن حساب را در مخزن قرار ندهید.
6. دکمهٔ ورود با گوگل دسترسی `spreadsheets.readonly` می‌گیرد. هنگام درخواست انتقال، اجازهٔ `spreadsheets` برای نوشتن جداگانه درخواست می‌شود.

## نقشهٔ ستون‌های بانک یکپارچه
A شناسه؛ B پاسخ نرمال؛ C پاسخ نمایشی؛ D تعداد حروف؛ E سرنخ؛ F دسته؛ G دشواری؛ H وضعیت؛ I نوع؛ J شناسهٔ منبع؛ K پیوند؛ L مجوز؛ M تأیید مستند؛ N یادداشت؛ O بازبین؛ P تاریخ؛ Q وضعیت سرنخ.

موتور «شرح در متن» فقط ردیف‌هایی را استفاده می‌کند که پاسخ، سرنخ و طول صحیح داشته باشند؛ همهٔ رکوردهای فاقد سرنخ صرفاً به‌عنوان واژهٔ بانک باقی می‌مانند. اگر جدول کامل نشود، آن را قابل انتشار نمی‌شمارد.

## مهاجرت ایمن بانک قبلی
1. **در همان مرورگر اصلی** صفحهٔ کارگاه پیشین را باز کنید و «پشتیبان کامل این مرورگر» را دانلود کنید. بانک ۱۹٬۸۰۴ مدخلی فقط در همان مرورگر ذخیره شده و از طریق GitHub قابل بازیابی نیست.
2. فایل کامل JSON نسخهٔ ۲ را در `sheets-studio.html` انتخاب کنید.
3. فایل با اثر انگشت SHA-256 بررسی می‌شود و همهٔ ردیف‌های آن از نظر ساختار کنترل می‌شوند.
4. پیش از هر انتقال، شیت خصوصی جدیداً از سرور خوانده شده و ردیف‌های تکراری با کلید پاسخ نرمال+سرنخ کنار گذاشته می‌شوند.
5. دکمهٔ انتقال پس از نشان دادن شمار واقعی افزودنی‌ها، **تأیید صریح** می‌خواهد. داده‌ها دسته‌ای با `values:append` اضافه می‌شوند؛ هیچ ردیف موجودی بازنویسی یا پاک نمی‌شود.
6. در صورت خطای شبکه/سهمیه، صفحه را مجدداً باز کنید و همان فایل را بررسی کنید؛ پیش از ادامه، رکوردهای موجود از سرور بازخوانی می‌شوند.
7. پس از انتقال، تعداد شیت و تعداد پرسش‌وپاسخ دارای سرنخ را بررسی کنید. انتقال و تأیید محتوا یکسان نیستند.

## مرزهای این فاز
- نسخهٔ جدید مستقل و غیرمخرب است. نسخهٔ قدیمی `index.html` و بانک مرورگر حذف نشده‌اند.
- این رابط فعلاً تولید خودکار «شرح در متن» و واردسازی غیرمخرب بانک را پوشش می‌دهد. اتصال سراسریِ سایر موتورهای کلاسیک/مینی و خط انتشار نهایی، فاز بعدی است.
- در ۲۰۲۶-۱۱-۰۳، Google Sheets API در `jadval-studio` فعال شد و کلاینت Web با نام `Jadval Sheets — GitHub Pages` و مبدأ `https://nimania.github.io` ساخته شد. مجوز `spreadsheets.readonly` در Data Access ثبت شده است.
- پروژه از قبل در حالت External / In production بود و این وضعیت تغییر نکرد؛ در این حالت فهرست Test users لازم نیست. دسترسی شیت همچنان به مالک آن محدود است.
- انتشار GitHub Pages و بارگذاری Client ID جدید تأیید شد. آزمون ورود با حساب مالک تا هشدار «Google hasn’t verified this app» پیش رفت. خواندن واقعی بانک و تولید جدول هنوز تأیید نشده و به تأیید دسترسی گوگل توسط کاربر نیاز دارد.
- هیچ شیت، ردیف، کلاینت قبلی یا اطلاعاتی حذف نشد و پروژهٔ YouTube تغییر نکرد.
- پیش‌نویس JSON به‌معنای انتشار عمومی نیست؛ دروازهٔ بازبینی سردبیری همچنان پابرجاست.
