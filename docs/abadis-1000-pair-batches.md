# بانک آبادیس — بسته‌های ۱۰۰۰ جفتی

## قرارداد داده

**واحد شمارش، «جفت سرنخ + پاسخ» است؛ نه پاسخ یکتا.** اگر «سیب» ۱۰ سرنخ واقعاً متفاوت داشته باشد، هر ۱۰ سرنخ باید به‌عنوان ۱۰ رکورد مستقل در بانک باقی بمانند.

کلید منطقی برای جلوگیری از تکرار، `(normalize(clue), normalize(answer))` است:
- تغییر فاصله، ی/ي، ک/ك، همزه‌های رایج و ارقام فارسی/لاتین، باعث ثبت تکراری نمی‌شود.
- دو سرنخ متفاوت برای یک جواب، هر دو حفظ می‌شوند.
- دو جواب متفاوت برای یک سرنخ می‌توانند در صف بازبینی بمانند تا معنای موردنظر روشن شود.
- ترتیب واژه‌های فارسی و متن خام سرنخ حفظ می‌شود؛ هیچ الگوریتمی کلمات سؤال را معکوس نمی‌کند.

`tools/abadis_prepare_import.py` چند فایل JSON برداشت را با بانک اصلی و صف اصلاح خصوصی تطبیق می‌دهد و خروجی را در فایل‌های حداکثر **۱۰۰۰ ردیفی** جدا می‌کند. این ابزار هیچ آپدیت مستقیمی روی شیت یا مخزن انجام نمی‌دهد.

## روند عملیاتی

1. اجرای محدود `tools/abadis_full_scan.py` با رعایت robots.txt و تأخیر دست‌کم ۲ ثانیه. سقف هر اجرای GitHub ۱۵۰ صفحهٔ جزئیات است، نه ۱۰۰۰ درخواست هم‌زمان.
2. دریافت artifact و `next_cursor` و مقایسه با Google Sheets خصوصی (شامل صف اصلاح).
3. نگهداری سرنخ‌های یکتا حتی اگر پاسخ در بانک موجود باشد.
4. ورود مورد ساختاری سالم به بانک با وضعیت «در انتظار بازبینی»؛ ورود مورد مشکوک به صف اصلاح، نه بانک آماده.
5. خواندن دوبارهٔ بازه‌های نوشته‌شده، سپس ثبت نشانگر ادامه و راه‌اندازی دستهٔ بعدی.
6. تکمیل هر بسته با افزودن **۱۰۰۰ جفت جدید غیرتکراری** از چند اجرای محدود؛ گزارش عددی و شناسنامهٔ منبع هر بسته.

شیت مرکزی:
https://docs.google.com/spreadsheets/d/1Cdai0EBDCNxbS9-UCbCWLGg7fNkk74joq7pbDr_fIEQ/edit

تب «بسته‌های هزار‌تایی آبادیس» با شمارش شناسه‌های منبع در ستون J بانک، تعداد مدخل‌های جدید را به‌صورت زنده محاسبه می‌کند. **مبنای این طرح ۳۷۶ مدخل آبادیس است**؛ بستهٔ ۱ از مدخل ۳۷۷ به بعد شروع می‌شود. رکوردهای موجود در «صف بازبینی آبادیس» در این شمارنده لحاظ نمی‌شوند تا قبل از اصلاح، به‌اشتباه جزو هزار جفتِ قابل استفاده شمرده نشوند.

## حفظ حقوق و کیفیت

- نسبت دادن منبع به آبادیس برای همهٔ جفت‌ها الزامی است؛ قبل از بازانتشار وسیع، حقوق استفاده از محتوا نیز باید بررسی شود.
- داده‌های خصوصی بانک را به مخزن GitHub عمومی یا GitHub Pages نریزید.
- خطاهای 403/429 یا محدودیت قطعی را دور نزنید؛ فرایند را متوقف کنید.
- پاسخ خالیِ یک صفحه به‌معنای پایان فهرست نیست.
- هر رکورد افزوده‌شده همچنان `reviewed=false` است؛ صحت معنایی جداگانه تأیید می‌شود.
- به‌ویژه سرنخ‌های دارای شکستگی فاصله و پاسخ‌های چندبخشی باید جداگانه بررسی شوند.
