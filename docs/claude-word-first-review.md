# بررسی و استفاده از الگوریتم واژه‌محور کلاد

این یادداشت بر اساس دو فایل ارسالی صاحب پروژه نوشته شده است:
`persian_crossword.py` و `crossword_output.json`. فایل‌های ارسالی یا
بانک سؤال‌وجواب به مخزن عمومی منتقل نشده‌اند.

## خروجی واقعی نمونهٔ ۱۵×۱۵
- ۴۳ پاسخ ثبت‌شده و یکتا؛ همه در محل‌های مشخص‌شده خوانده می‌شوند.
- ۱۰۸ خانهٔ حرف‌دار و ۱۱۷ خانهٔ سیاه (۵۲٪ شبکه).
- هر ۱۵ سطر و ستون دست‌کم یک خانهٔ حرف‌دار دارند.
- ۶۵ قطعهٔ تک‌حرفی افقی/عمودی؛ هر خانهٔ حرف‌دار عضو دست‌کم یک واژهٔ ثبت‌شده است،
  ولی این با شرط «هر قطعهٔ افقی/عمودی باید واژهٔ چندحرفی داشته باشد» یکسان نیست.
- طول جواب‌های افقی/عمودی با تقاطع‌ها مطابقت دارد؛ این نمونه صرفاً از SAMPLE
  داخل کد کلاد استفاده می‌کند و سرنخ‌های بانک خودمان را ندارد.
- بنابراین **این خروجی آمادهٔ انتشار نیست** و «تأیید معتبر بودن تمام
  ۲۲۵ خانه» در معنای استاندارد کلاسیک نباید از آن برداشت شود.

## بخش‌های فنی قابل استفاده
1. **جهت فارسی درست**: آرایهٔ فیزیکی ستون‌ها چپ به راست است، اما پاسخ افقی
   از راست به چپ و پاسخ عمودی از بالا به پایین خوانده می‌شود.
2. **ردگیری مالکیت جهت** (`occA`, `occD`): یک پاسخ افقی دیگر نمی‌تواند
   روی جواب افقی موجود قرار بگیرد؛ تقاطع افقی/عمودی مجاز است.
   این کنترل با حفظ API در فایل `generate.py` اضافه شد.
3. **روش واژه‌محور با تقاطع الزامی**: برای ساخت اولیهٔ اسکلت می‌تواند
   ارزان‌تر از جست‌وجوی کامل روی یک شبکهٔ تصادفی باشد؛ ولی به‌تنهایی
   تراکم و کیفیت استاندارد را تضمین نمی‌کند.
4. **شماره‌گذاری دوگانه**: نمونهٔ کلاد شماره‌گذاری کلاسیک آغاز واژه و
   شماره‌گذاری کناری سطر/ستون را ارائه می‌دهد؛ محصول ما حالت کناری ۱..۱۵ دارد.
5. **اعتبارسنجی مستقل**: `generate.audit_draft` اکنون قطعه‌های
   تک‌حرفی، رشته‌های چندحرفی ثبت‌نشده، خانه‌های بی‌مالک، پوشش همهٔ سطرها
   و ستون‌ها و نسبت خانه‌های سیاه را ثبت می‌کند.

## تبدیل JSON کلاد به فرمت جدول
`tools/convert_claude_crossword.py` فقط به‌صورت محلی کار می‌کند.
جدول را می‌خواند و **متن سؤال را از بانک محلی** به پاسخ‌ها وصل می‌کند.
اگر جوابِ بدون سؤال، ورود نامعتبر یا اختلاف تقاطع وجود داشته باشد، خطا می‌دهد.

```bash
python3 tools/convert_claude_crossword.py \
  --input /path/to/crossword_output.json \
  --bank /path/to/jadval_entries_19804.json \
  --output /path/to/claude-import-draft.json
```

`--strict` برای جلوگیری از خروجیِ شبکهٔ دارای قطعهٔ تک‌حرفی،
ردیف/ستون غیرفعال یا بیش از ۳۰٪ خانهٔ سیاه است. نمونهٔ ارسالی
به‌دلیل ۵۲٪ سیاه و ۶۵ قطعهٔ تک‌حرفی از این فیلتر عبور نمی‌کند.

نکته: مختصات `c` در مدخل‌های افقی خروجی کلاد «چپ‌ترین خانه» است؛
در فرمت v3، خواندن رشتهٔ افقی از راست‌ترین خانه شروع می‌شود.
مبدل این تفاوت را کنترل می‌کند.

## مسیر توسعهٔ موتور ۱۵×۱۵
ترکیب مطلوب: **واژه‌محور برای ساخت هسته → اصلاح محلی جایگاه‌های قرمز
→ حل‌گر قیدی برای تکمیل تمام تقاطع‌ها → اعتبارسنجی سختگیرانه و کنترل شباهت**.
تا آن زمان خروجی‌های روش واژه‌محور صرفاً پیش‌نویس‌اند، با
`_draft.publication_ready=false`، و هیچ چیزی به `payamejadval`
انتقال داده نمی‌شود.
