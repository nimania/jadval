# اتصال بانک سؤال‌وجواب Jadval به Firebase خصوصی

## چه چیزی پیاده‌سازی شده است؟
- رابط سایت `index.html` اکنون بخش «پایگاه دادهٔ مرکزی Jadval» دارد.
- `cloud-bridge.js`: ورود مدیر با Google Authentication، بررسی سند مدیر،
  دریافت رکوردهای Firestore، ذخیرهٔ ویرایش با کنترل نسخه، و مهاجرت اولیهٔ
  مرحله‌ای از داده‌های مرورگر.
- `firebase-config.js`: پیکربندی عمومی وب. فعلاً **خالی** است؛ هیچ
  پروژهٔ Firebase به سایت متصل نشده.
- `firebase/firestore.rules`: دسترسی محدود به مدیران صریحاً تأییدشده؛
  کاربر صرفاً با ورود گوگل دسترسی به بانک ندارد.
- `firebase.json`: استقرار فقط قواعد Firestore، نه انتشار بانک در Pages.
- در صورت قطع اتصال هنگام ذخیرهٔ ویرایش، مدخل در کلید
  `pending-cloud-edits` در IndexedDB نگه داشته و دریافت مجدد نسخهٔ
  ابری تا رسیدگی به این تعارض مسدود می‌شود.
- دکمهٔ دریافت آخرین تغییرات بعد از ورود از سرور می‌خواند.
  *همگام‌سازی لحظه‌ای WebSocket* فعلاً پیاده نشده است.

## راه‌اندازی مرحله‌به‌مرحله

### ۱) پروژهٔ مستقل
یک پروژهٔ اختصاصی مانند `jadval-studio` در
[Firebase Console](https://console.firebase.google.com/) بسازید؛
از پروژهٔ جدول انار فقط به‌عنوان منبع دارای مجوز استفاده شده است و
دیتابیس مشترک یا دسترسی نوشتن به آن لازم نیست.

در پروژهٔ جدید:
- Firestore Database را در حالت **Production / locked** ایجاد کنید.
- Authentication → Sign-in method → Google را فعال کنید.
- Authentication → Settings → Authorized domains:
  دامنهٔ `nimania.github.io` را اضافه کنید.
- در Project settings → Your apps → Web، اپ وب ایجاد کرده و
  مقادیر `apiKey`، `authDomain`، `projectId` و `appId`
  را بردارید. این‌ها تنظیمات عمومی هستند؛ **کلید سرویس اکانت نیستند.**

### ۲) فعال‌کردن پیکربندی و قواعد امنیتی
در ریپوی `nimania/jadval`، فقط مقادیر عمومی بالا را در
`firebase-config.js` قرار دهید. هیچ فایل JSON رمزآلود یا
service-account key در GitHub قرار ندهید.

قواعد `firebase/firestore.rules` را در Firestore Rules در
Firebase Console منتشر کنید؛ یا با Firebase CLI:

```bash
firebase login
firebase deploy --only firestore:rules --project YOUR_PROJECT_ID
```

**احتیاط:** تنظیمات کلاینت و قواعد امنیتی باید متعلق به همان پروژه باشند.
تا انتشار قواعد محدودکننده از فعال‌کردن نوشتن عمومی خودداری کنید.

### ۳) دادن دسترسی مدیر
در برنامه با گوگل وارد شوید. تا سند مدیر وجود نداشته باشد، برنامه
به بانک اجازهٔ دسترسی نمی‌دهد و UID حساب را نمایش می‌دهد.
مالک پروژه از Firebase Console در Firestore سند
`admins/<UID>` با فیلد بولی `enabled: true` ایجاد می‌کند.
سپس یک‌بار خارج و دوباره وارد شوید.

تنها اتصال گوگل **کافی نیست**؛ سند مدیر به‌طور خودکار ایجاد نمی‌شود.

### ۴) انتقالِ اولیه (فقط یک‌بار)
در **همان مرورگری** که بانک اصلی ۱۹٬۸۰۴مدخلی و ویرایش‌ها در آن است:
۱. قبل از هر کاری «خروجی و پشتیبان JSON» بگیرید و فایل را خارج از
   مرورگر ذخیره کنید.
۲. به `https://nimania.github.io/jadval/` بروید؛ با حساب مدیر وارد شوید.
۳. وضعیت پایگاه مرکزی باید «خالی» باشد.
۴. روی **انتقال بانک این مرورگر به سرور** بزنید و شمار مدخل‌ها را
   بررسی و تأیید کنید. انتقال در دسته‌های ۱۰۰رکوردی انجام می‌شود و
   به‌طور خودکار داده‌های موجود را overwrite نمی‌کند.
۵. در صورت قطعی، **در همان مرورگر** اتصال را تکرار و انتقال را
   ادامه دهید. سند `meta/bank` با وضعیت `importing` تا پایان
   انتقال باقی می‌ماند؛ وقتی شمار داده‌ها تأیید شد `ready` می‌شود.
۶. پس از آماده‌شدن، با دستگاه دوم وارد شوید: دیگر فایل JSON
   به‌طور دستی وارد نمی‌شود؛ رکوردها از Firestore دریافت خواهند شد.

**محدودیت مهم:** ۱۹٬۸۰۴ رکورد به‌معنای تقریباً همین تعداد
عملیات نوشتن در انتقال اولیه و خواندن در نخستین بارگذاری هر دستگاه
است. سهمیه و هزینهٔ Firestore را در Firebase Console کنترل کنید.
این نسخه برای مدیریت اولیه است؛ صفحه‌بندی سمت سرور و کش بهینه‌تر
برای کاهش هزینه در نسخهٔ بعد مناسب‌اند.

### ۵) ویرایش‌ها و تعارض‌ها
وقتی بانک مرکزی فعال است، ویرایش هر مدخل با `revision`
در Firestore ذخیره می‌شود. اگر مدخل در دستگاه دیگری تغییر کرده
باشد، ذخیرهٔ نسخهٔ قدیمی رد می‌شود تا تغییری بی‌صدا از بین نرود.
خطا در دستگاه محلی به‌صورت `pending-cloud-edits` نگهداری می‌شود؛
تا رسیدگی به آن، دانلود مجدد بانک مرکزی مسدود خواهد بود.

محدودیت اجرایی: رابط رسیدگی و ادغام ویرایش‌های معلق هنوز ساخته نشده؛
تا رفع این مورد باید از «خروجی و پشتیبان JSON» استفاده شود و
تغییرها را به‌صورت دستی بررسی کرد.

### ۶) پشتیبان مستقل و دوام داده
- `IndexedDB` مرورگر اولیه برای حفظ آرشیو تا پایان مهاجرت حذف نمی‌شود.
- ذخیرهٔ فایل JSON قبل و بعد از واردسازی ضروری است.
- Firebase Firestore نسخهٔ پشتیبان مستقل را خودکار در این پروژه
  تنظیم نمی‌کند؛ خروجی‌گیری زمان‌بندی‌شده، کنترل دسترسی و آزمون بازیابی
  باید بعد از اتصال واقعی اجرا شوند.
- بانک اصلی/پیش‌نویس‌ها هرگز در GitHub Pages عمومی یا
  `payamejadval` منتشر نمی‌شوند.
- تا فعال‌سازی Firebase، وضعیت سایت **فقط مرورگر محلی** باقی می‌ماند.

## وضعیت فعلی و کار باقی‌مانده
**کد اتصال و قواعد در GitHub آماده است، اما پروژهٔ Firebase هنوز
متصل و مهاجرت واقعی انجام نشده است.** تا دریافت پیکربندی پروژه،
هیچ حساب مدیریتی یا مجموعهٔ Firestore به‌طور خودکار ساخته نمی‌شود.
