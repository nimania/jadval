# مهاجرت امن بانک سؤال‌وجواب Jadval به پایگاه دادهٔ مرکزی

## وضعیت فعلی
- برنامهٔ `index.html`، داده‌ها و ویرایش‌ها را در IndexedDB هر مرورگر نگه می‌دارد.
- `build_database.py` یک SQLite مستقل را از آرشیو دارای مجوز می‌سازد، اما
  فایل اصلی در GitHub Actions فقط به‌صورت artifact با مهلت ۳۰روزه ذخیره می‌شود.
- GitHub Pages فقط میزبان فایل‌های استاتیک است و **پایگاه دادهٔ خصوصی/سروری نیست**.

## طرح پیشنهادی (برای اجرا پس از آماده‌شدن حساب مالک پروژه)
۱. ایجاد **Firebase project اختصاصی Jadval** (از منبع Anar جدا).
۲. Firestore خصوصی + Firebase Authentication؛ فقط شناسه‌های مدیریتی مجاز
   بتوانند سؤال‌وجواب‌ها را بخوانند/ویرایش کنند.
۳. ساختار:
   - `entries/{entryId}`: سؤال، جواب نرمال‌شده، موضوع، درجه سختی،
     `reviewed`, منبع، مجوز، زمان و شناسهٔ نسخه.
   - `puzzles/{puzzleId}`: پیش‌نویس‌ها و الگوها با وضعیت بازبینی.
   - `auditLogs/{eventId}`: زمان، ویرایشگر، نوع تغییر، شناسهٔ مدخل و
     نسخهٔ قبل/بعد؛ دسترسی فقط به مدیر.
   - `admins/{uid}`: مجوزهای اعطاشده فقط از محیط مدیریتی Firebase.
۴. واردسازی اولیه **یک بار و با پیش‌نمایش**. منبع اول باید آخرین خروجی
   JSON از مرورگری باشد که ویرایش‌های کاربر در آن انجام شده؛ با آرشیو
   ۱۹٬۸۰۴مدخلی مقایسه و همسان‌سازی شود. هرگونه تعارض باید قبل از
   بارگذاری نهایی فهرست و تصمیم‌گیری شود.
۵. بعد از همگام‌سازی و راستی‌آزمایی شمار مدخل‌ها، Firestore منبع اصلی
   شود؛ IndexedDB فقط cache آفلاین (با برچسب وضعیت sync) باقی بماند.
۶. خطای شبکه/اجازه باید به‌صراحت نمایش داده شود، نه اینکه برنامه بانک خالی
   را به‌عنوان حقیقت تلقی کند. هر ویرایش با کنترل نسخهٔ رکورد انجام شود.
۷. پشتیبان خودکارِ نسخه‌دار در فضای خصوصی جدا از سایت عمومی، و آزمون
   بازیابی برای جلوگیری از آسیب داده.

## حفاظت
- **هیچ سؤال‌وجوابی در public GitHub repository، Pages یا کد frontend hardcode نشود.**
- Firebase web API key به خودی خود رمز محرمانه نیست؛ مجوز اصلی از
  Firebase Auth + Firestore Security Rules می‌آید.
- قواعد امنیتی نمونه در `firebase/firestore.rules` «پیش‌فرض رد»
  هستند. تا مدیر واقعی از طریق Admin SDK در `admins/{uid}` ثبت نشود
  هیچ کس اجازهٔ دیدن بانک را ندارد.
- هیچ کلید خصوصی service account در گیت‌هاب، متن گفتگو یا frontend نباشد.
  برای عملیات مدیریتی از Secretهای ایمن و حداقل دسترسی استفاده شود.

## وضعیت اجرا
- این فایل و قواعد پایه آماده‌سازی معماری هستند؛ **اتصال زنده یا
  مهاجرت بانک هنوز انجام نشده است**.
- نباید تا پایان انتقال، IndexedDB مرورگر فعلی پاک یا بازنویسی شود.
- انتشار در `payamejadval` همچنان فقط پس از تأیید انسانی مجاز است.
