# جدول | Jadval Studio

کارگاه داخلی طراحی جدول فارسی؛ بانک سؤال‌وجواب، دریافت آرشیو دارای مجوز، طراحی جدول، بازبینی و تحویل خروجی نهایی به [پیام جدول](https://github.com/nimania/payamejadval).

## وضعیت اجرا (مرحلهٔ واردسازی)
- `fetch_archive.py`: خواندن فهرست `catalog/index` و همهٔ بسته‌های `puzzlePacks/*` جدول انار از Firestore، سپس ذخیرهٔ مستقل هر جدول JSON.
- `build_database.py`: استخراج سؤال و جواب از جدول‌های JSON و ساخت پایگاه SQLite مستقل همراه با جدول‌های `puzzles`، `entries` و `occurrences`.
- `import_puzzles.py`: واردکنندهٔ محلی فایل‌های JSON دارای مجوز.
- `generate.py`: نمونهٔ اولیهٔ موتور تولید جدول (کیفیت خروجی هنوز برای انتشار خودکار تأیید نشده است).
- `sample.json`: نمونهٔ آزمایشی.

**داده‌های واقعی هنوز وارد نشده‌اند.** برای شروع انتقال باید گردش‌کار را از GitHub Actions اجرا کنیم.

## اجرای دریافت کامل آرشیو
۱. نیازی به تهیهٔ کلید یا ساخت Secret نیست؛ کلید عمومی وب Firebase از پیکربندی منتشرشدهٔ جدول انار استفاده می‌شود. این کلید مجوز دسترسی اضافه‌ای نمی‌دهد.
۲. در [Actions](https://github.com/nimania/jadval/actions/workflows/import-archive.yml)، گردش‌کار **Import licensed crossword archive** را با `Run workflow` اجرا کنید.
۳. خروجی اجرای موفق را از بخش **Artifacts** همان اجرا دریافت کنید: پوشهٔ `archive/raw` شامل جدول‌های اصلی JSON، فایل `archive/jadval.sqlite` شامل بانک استخراج‌شده و `archive/report.json` شامل آمار واقعی است.

**نکتهٔ حفاظت از داده:** آرشیو واقعی در این مرحله در git push نمی‌شود و فقط به شکل artifact با مدت نگهداری ۳۰ روز موجود است. برای نگهداری دائمی باید مخزن خصوصی/فضای ذخیره‌سازی مناسب تنظیم شود. پایگاه Firebase منبع تغییری نمی‌کند. اگر Firestore دریافت را رد کند، دسترسی معتبر یا خروجی پشتیبان از مالک داده لازم خواهد بود.

## اجرای محلی
```bash
python3 fetch_archive.py --output archive/raw
python3 build_database.py --archive archive/raw --db archive/jadval.sqlite --report archive/report.json
python3 generate.py --input sample.json --size 15 --count 3
```

## مرز انتشار
`nimania/jadval` فقط ابزار داخلی است. بانک خام، همهٔ پاسخ‌ها، و پیش‌نویس‌ها نباید به وب‌سایت مخاطبان ارسال شوند. `nimania/payamejadval` فقط جدول‌های انتخاب و تأییدشده را نمایش می‌دهد.

## کارهای باقیمانده
- اجرای موفق دریافت واقعی و خواندن گزارش شمارش جدول‌ها و مدخل‌ها.
- ساخت پنل دسته‌بندی و ویرایشگر حرفه‌ای راست‌به‌چپ.
- ارتقای الگوریتم تولید و اعتبارسنجی جدول‌های کامل.
- طراحی سازوکار انتشار جدول‌های تأییدشده از jadval به payamejadval.

## گزارش بازبینی آرشیو (۳۱ اکتبر ۲۰۲۶)

نخستین خروجی ۳۲۴ جدول را بدون خطای ساختاری دریافت کرد، اما کنترل نمونه نشان داد نسخهٔ اولیهٔ واردکننده ترتیب رشته‌های افقی و شماره‌گذاری ستون‌های منبع را برعکس می‌خواند. واردکننده اصلاح شد؛ بازسازی از روی همان آرشیو ۳۲۴ جدول، **۱۹٬۸۰۴ جفت سؤال/جواب یکتا**، **۱۱٬۴۱۹ جواب متفاوت** و **۲۸٬۷۰۴ رخداد** تولید کرد. این اعداد نتیجهٔ بازسازی و بازبینی هستند، نه ادعای صحّت نهایی تک‌تک سؤال‌ها. فایل‌های منبع دست‌نخورده‌اند. برای دریافت مجدد می‌توان گردش‌کار را دوباره اجرا کرد؛ بخش واردسازی اکنون از الگوریتم اصلاح‌شده استفاده می‌کند.

## پنل مدیریتی — مرحلهٔ دوم
رابط فارسی `index.html` در مخزن قرار گرفت. GitHub Actions فقط همین فایل را برای GitHub Pages منتشر می‌کند؛ **بانک سؤال‌وجواب، نسخه‌های آرشیوی و فایل SQLite در خروجی عمومی قرار نمی‌گیرند**.

۱. فایل `jadval_entries_19804.json` را از خروجی بررسی آرشیو دریافت کنید (۱۹٬۸۰۴ سؤال‌وجواب، حاصل بازسازی صحیح ۳۲۴ جدول).
۲. به `https://nimania.github.io/jadval/` بروید. اگر هنوز فعال نشده، در Settings → Pages منبع را GitHub Actions انتخاب کنید، سپس گردش‌کار **Publish Jadval Studio UI** را اجرا کنید.
۳. دکمهٔ **ورود بانک JSON** را بزنید. داده‌ها در IndexedDB مرورگر نگهداری می‌شوند؛ خبری از بارگذاری محتوای بانک روی سرور نیست.
۴. جست‌وجو، موضوع، درجه سختی، وضعیت بازبینی و ویرایش مدخل‌ها در دسترس است. «دسته‌بندی پیشنهادی» بر اساس قواعد اولیه است و برچسب‌هایش نیاز به کنترل انسانی دارند.
۵. پس از ویرایش، حتماً از **خروجی و پشتیبان JSON** استفاده کنید.

**محدودیت مهم:** SQLite هنوز به سرور مرکزی متصل نشده؛ دادهٔ داخل مرورگر شخصی است و تغییرات بین مرورگرها همگام نیست. برای نگهداری دائمی و کار چندکاربره به مخزن دادهٔ خصوصی یا سرور احراز هویت‌شده نیاز داریم. فایل بانک را به مخزن عمومی commit نکنید.

صفحهٔ بازی نهایی و اتصال انتشار به پیام جدول گام بعدی هستند.

## نسخهٔ آزمایشی ۲ — جدول با خانه‌های سیاه محدود
در `sparse-generator.js` موتور مستقل تولید الگوی کم‌سیاه و جست‌وجوی CSP اضافه شده است:
- حداکثر **۲ خانهٔ سیاه در هر ردیف و هر ستون**؛ خانه‌های سیاه باید حداقل دو خانه فاصله داشته باشند.
- جایگاه‌های یک‌حرفی و جدول ناقص رد می‌شوند؛ هیچ جای خالی به‌صورت خودکار سیاه نمی‌شود.
- متن سرنخ‌ها از بانک موجود برداشته می‌شود؛ تعداد حروف و اندیس‌های (۱)/(۲) نمایش داده نمی‌شود.
- گزینه‌های آزمایشی ۵×۵، ۷×۷، ۱۰×۱۰ و ۱۵×۱۵؛ برای اندازه‌های بزرگ نتیجه **تضمین نشده** و در صورت نبود جواب معتبر پیام خطا نمایش داده می‌شود.
- یک **نمونهٔ معتبر و کامل ۵×۵** از ترکیب جدید ده مدخل بانک موجود، بدون خانهٔ سیاه، اضافه شد. مقایسهٔ مجموعهٔ پاسخ‌های آن با ۳۲۴ جدول اصلی نشان داد بیشترین اشتراک پاسخ‌ها ۱ از ۱۰ (۱۰٪) است.
- آستانهٔ عدم‌تشابه بالای ۸۰٪ در تولید عمومی **هنوز اعمال نمی‌شود**، چون بانک مرورگر فاقد اثرانگشت نسخهٔ اصلی همهٔ جدول‌هاست؛ تا تکمیل کنترل شباهت انتشار خودکار ممنوع است.

ورودی بانک قبلی در IndexedDB مرورگر حفظ می‌شود. این تغییرات به `payamejadval` هیچ جدول جدیدی ارسال نمی‌کنند.

## نسخهٔ آزمایشی ۳ — شرط الزامی ۱ یا ۲ سیاه در همهٔ سطرها و ستون‌ها (۳۱ اکتبر ۲۰۲۶)
- طرح‌های جدید `sparse-generator.js` در **هر ردیف و هر ستون** حداقل ۱ و حداکثر ۲ خانهٔ سیاه دارند؛ در ۲۰×۲۰ الگوی فعلی ۲۴ خانهٔ سیاه دارد.
- اندازه‌های قابل انتخاب: ۷×۷، ۱۰×۱۰، ۱۵×۱۵ و **۲۰×۲۰** (پیش‌فرض).
- الگوی ۵×۵ بدون خانهٔ سیاه از دسترس خارج شده است.
- در صورت یافتن راه‌حل کامل CSP، همهٔ خانه‌های غیرسیاه با پاسخ‌ها پر می‌شوند. در صورت نیافتن، یک **پیش‌نویس ناقص** با خانه‌های سفید بدون حرف و تعداد جواب‌های تکمیل‌شده نمایش داده می‌شود؛ این فایل `version:0` و `status:partial-draft` دارد، با قالب معتبر انتشار `version:3` اشتباه نشود.
- خانهٔ سفیدِ بدون جواب دیگر به‌عنوان خانهٔ سیاه نمایش داده نمی‌شود. سؤال‌های استفاده‌شده از بانک محلی و بدون تعداد حروف ارائه می‌شوند.
- **محدودیت واقعی:** در بانک ۱۹٬۸۰۴مدخلی بسیاری از جایگاه‌های بلند ۲۰×۲۰ جواب مناسب ندارند. تولید جدول استاندارد کاملاً پُرِ ۲۰×۲۰ همچنان تضمین نشده؛ حالت پیش‌نویس برای دیدن و اصلاح چیدمان است. هنوز ابزار ویرایش خانه‌ها و تأیید نهایی راه‌اندازی نشده است.
